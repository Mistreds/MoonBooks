# Формат Moon+ Reader: рабочая гипотеза

Это описание **не проверено на телефоне**. Реального устройства с Moon+ Reader в этой задаче не было, поэтому синхронизация с телефоном не считается подтверждённой. Ниже — то, на что опирается MoonBooks, и что нужно сверить вручную.

## Где лежат файлы

Корень книг по умолчанию — папка `Books/` (её можно сменить в настройках).

Позиция чтения, как мы её понимаем:

```text
Books/.Moon+/Cache/<имя файла книги>.po
```

Имя файла книги — исходное, вместе с расширением. Пример: `Books/.Moon+/Cache/Маяк.fb2.po`. Кириллица в имени допустима; кодек разбирает только тело файла, не имя.

Данные, которые есть только у MoonBooks (полки, жанры, настройки чтения), пишутся **рядом**, а не внутрь `.Moon+`:

```text
Books/.MoonBooks/moonbooks.json
```

У документа есть `schemaVersion` (сейчас 1). Слияние поэлементное, побеждает более поздняя метка времени. Удаления между устройствами не синхронизируются.

## Главный риск Google Drive

Moon+ может хранить кэш в обычной папке Диска, которую видит клиент с scope `drive`. Либо он может писать в `appDataFolder` приложения, и тогда чужой клиент эти файлы не увидит.

Scope `drive.file` видит только файлы, которые создало само приложение, и **не видит** файлы Moon+. В настройках это написано явно: нужен ограниченный scope `drive`. Идентификатор и секрет OAuth-клиента в репозиторий не входят и по умолчанию пустые. Пока они не заданы, проверка соединения завершается состоянием «не настроен».

## Тело файла `.po`

Одна строка:

```text
timestamp*chapterIndex@splitIndex#positionInChapter:percent%
```

| Поле | Смысл гипотезы |
| --- | --- |
| `timestamp` | Unix-время в миллисекундах |
| `chapterIndex` | Номер главы с нуля |
| `splitIndex` | Номер куска длинной главы. `0` — смещение считается от начала главы |
| `positionInChapter` | Смещение внутри куска |
| `percent` | Процент книги, целое (`45%`) или дробное (`45.5%`) |

Примеры:

```text
1710000000000*2@0#150:45%
1710000000000*2@3#15:45.5%
```

Если `splitIndex` равен 0, `positionInChapter` — это смещение в нормализованном простом тексте главы (см. `PlainText`: блоки по порядку, между ними один `\n`, хвостовые пробелы абзаца отброшены, разметка не считается).

Если `splitIndex` не ноль, длина куска **неизвестна**. В коде временно принято 10 000 символов (`MoonPlusPositionMapper.AssumedSplitLength`). Это число нужно замерить на устройстве и поправить в одном месте.

Если число глав у Moon+ и у нас не совпадает, позиция берётся из процента и `TotalChars`, а не из номера главы.

Процент в базе MoonBooks хранится в пунктах от 0 до 100. Если удалённая позиция новее и отличается больше чем на 5 пунктов, приложение спрашивает: «На другом устройстве вы на 45%, перейти?». Есть настройка принять её автоматически.

## Что сознательно не сделано

Закладки и выделения Moon+ в этом формате не описаны и **не синхронизируются**. Локальная закладка MoonBooks остаётся только на этом компьютере.

Удаление книг на одном устройстве не удаляет их на другом.

Нужно проверить на телефоне:

1. Точный путь `.po` для WebDAV и для Google Drive, включая случай `appDataFolder`.
2. Реальные строки `.po`: порядок полей, целый и дробный процент, ненулевой `splitIndex`, длинная глава.
3. Совпадает ли `positionInChapter` при `splitIndex = 0` с правилом `PlainText` для FB2 и EPUB.
4. Как Moon+ называет файл для EPUB (внутреннее имя или имя файла на диске).
5. Пишет ли Moon+ что-нибудь про закладки и выделения рядом с `.po`.
